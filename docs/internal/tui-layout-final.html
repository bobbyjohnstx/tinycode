Tab 1: Idle -- No Goal Active

The default state. Maximum chat area, minimal chrome. The status bar is a single line showing agent, model, provider, effort level, and context usage. No goal tracker visible -- it only appears when /goal is invoked.

  • Status bar: 1 line. Agent name in primary color, model/provider/effort in muted, context percentage in info blue. Dot-separated for scannability.
  • Prompt: Thin horizontal rule (primary color) separates chat from input. Cursor blinks alone -- no decorative box.
  • Chat area: Full ~108 columns of usable width. Tool calls show inline with status badges. Diffs render with full-width colored backgrounds.
  • Key insight: This state is identical to the original Layout A. The goal tracker is purely additive -- it grows the status bar when needed, never takes permanent space.

Tab 2: Goal Active -- Autonomous Execution

When /goal all tests pass is invoked, the status bar expands from 1 line to 4 lines. The chat area shrinks by exactly 3 rows to accommodate the goal tracker. The expansion feels natural -- it's the same status region growing, not a separate panel.

  • Goal box: Bordered with primary color #c87898 using box-drawing characters. Header shows the goal description and iteration count (3/10). The border is the only place primary color is used densely -- it makes the goal tracker feel like a "live zone" without clashing with chat content.
  • Step icons: ✓ done (success green), ⚡ in-progress (warning amber, pulsing), ○ pending (dim gray). Steps flow left-to-right in the first row, budget/iterations in the second row.
  • Normal status bar: Remains underneath the goal box, unchanged. Agent/model/provider/effort/context in the same format as idle state.
  • The running indicator pulses to show the tool is actively executing. This matches the existing spinner pattern in tinycode's StatusBar.

Tab 3: Goal Complete -- Success State

When the goal condition is met, the goal tracker box collapses to a single summary line. After ~5 seconds, this line fades and the status bar returns to the idle 1-line state. The user sees a brief confirmation without permanent clutter.

  • Success line: ✓ Goal met: in success green, followed by the goal description and stats (iterations used, tokens consumed). This gives closure -- the user knows exactly what happened and what it cost.
  • No border box: The completed goal doesn't need the bordered tracker. A single line is sufficient because there are no in-progress steps to show. The transition from 4-line box to 1-line summary feels like the tracker "resolving" itself.
  • Status bar underneath: Unchanged. The normal agent/model line sits directly below the goal summary.
  • Auto-collapse: After 5 seconds, the success line disappears and the status bar returns to idle state (Tab 1). This prevents stale goal info from lingering. The user can always check /goal history via /history.

Tab 4: With Left Nav -- C Layout + Goal Tracker

Demonstrates that the goal tracker works identically when the left navigation rail is visible. The goal box spans the full terminal width (below both panels), while the chat area is narrower (~78 columns) due to the 28-column left rail.

  • Left rail (~28 columns): Three sections -- Sessions (with parent/child tree via └ connector), Agents (quick-switch list with active highlight), and MCP (connection status with error states in red).
  • Session tree: Shows "Debug websocket" as a child of "Fix server tests" using the └ branch connector. This visualizes the /branch feature -- forked sessions appear as children of their parent.
  • Goal box position: Spans full width, below both the left rail and chat area. This is intentional -- the goal is a global state, not scoped to either panel. The box-drawing border runs edge to edge.
  • MCP section: Shows 1 connected server (filesystem, green dot) and 1 errored server (google-docs, red dot with "err" label). Gives at-a-glance infrastructure health.
  • Chat area: Narrower but still usable at ~78 columns. Tool call lines and diffs wrap earlier but remain readable. The prompt separator and input are scoped to the chat pane.
