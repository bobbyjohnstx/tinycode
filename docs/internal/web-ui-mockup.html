Tab 0: Home -- Landing Page

The first thing users see when opening tinycode in a browser. The goal is to get them into a session within one click, not to impress them with a dashboard. Inspired by opening a notebook, not a control panel.

  • Wordmark, not logo: "tinycode" in JetBrains Mono at 22px with the pink accent (#c87898). Understated -- the tool is the product, not the branding. No tagline, no description. If you're here, you know what this is.
  • New Session button: Full-width pill shape, pink background (#c87898) with dark text. This is the only saturated element on the page -- it pulls focus immediately. The pill radius (100px) is intentionally different from the rest of the UI's 4-8px radii to mark it as the primary call-to-action.
  • Session list: Grouped by date (Today / Yesterday / Last week). Each row uses JetBrains Mono for the title to match how sessions appear in the TUI. Agent names in blue (#5c9cf5) give you context at a glance. The child session "try different approach" uses the same ::before / ::after connector lines as the sidebar tab, showing /branch parentage.
  • No status bar: Unlike the chat tabs, the home page has no bottom status bar. Instead, connection info and project path are a single muted line at the bottom of the content area. You're not in a session yet -- there's no agent, no context window, no effort level to show.
  • What's missing on purpose: No project picker (the project is already configured in web mode). No search (there are only a handful of sessions). No settings. No onboarding wizard. The TUI doesn't have any of this friction either -- you start it and you're immediately in a session. The web landing page should feel the same: one click away from working.
  • 680px max-width: Narrower than the 1200px app frame. The session list doesn't need wide space -- tight content feels more deliberate and focused. The vertical centering with padding-top: 80px gives breathing room without feeling empty.

Tab 1: Chat -- Main Conversation View

The default state with no sidebar. Maximum space for conversation. Translates the TUI's focused layout into a browser-native experience.

  • User messages: Blue left bar (#5c9cf5) matches the TUI's ┃ border character. The bar is 3px wide, not a full bubble -- keeps the same visual weight as the TUI without looking like a chat app.
  • Tool calls: Compact row with pink tool name, muted args, duration, and status badge. Clickable to expand output. Same information as TUI's inline tool calls, but interactive.
  • Diff blocks: Same diff colors as TUI: added #20303b background, removed #37222c. File header bar for context. Richer than TUI because the browser can do full syntax highlighting.
  • Prompt area: Pink top border (#c87898) mirrors TUI's pink horizontal rule separator. Multi-line textarea with JetBrains Mono. Agent/model metadata line below, same data as TUI status bar but compact.
  • Status bar: Bottom-pinned, same order as TUI: agent (pink) · model · provider · effort · context%. Adds a visual context meter bar since the browser has room for it. Idle dot replaces TUI's cursor-block indicator.

Tab 2: Goal Active -- Autonomous Execution

When /goal all tests pass is active, the goal tracker expands between the prompt and the status bar. Same information as TUI's bordered box, adapted for the browser.

  • Goal tracker box: Pink border (#c87898) matching the TUI exactly. Background is #0f0a0c (the TUI's bg-goal). Rounds corners because the browser supports it -- the TUI uses box-drawing characters for the same visual separation.
  • Step icons: ✓ done, ⚡ in-progress (pulsing), ○ pending -- identical to TUI. Steps flow horizontally in a flex row that wraps on narrow screens.
  • Running tool: The active shell call gets a warning-color left border accent and a CSS spinner (replacing TUI's text-based spinner). The "running" label pulses.
  • Status bar spinner: The idle dot becomes a spinning indicator when work is in progress. Same semantic as TUI's SetWorking(true) spinner.
  • Layout impact: The goal tracker takes ~80px of height. The chat area scrolls to accommodate, unlike the TUI where chat rows are consumed. Browser scrolling is more natural here.

Tab 3: With Sidebar -- Session Management

The left sidebar shows sessions, agents, and MCP status. It mirrors the TUI's left nav (Tab 4 in the TUI mockup) but uses mouse-driven interactions instead of keyboard navigation.

  • Session hierarchy: "Debug websocket" appears indented under "Fix server tests" with a connecting line, showing the /branch parent-child relationship. Same tree concept as TUI's └ connector, rendered as CSS pseudo-elements.
  • Active indicators: Pink dot (#c87898) marks the current session. Hover states use #1a1a1a, a half-step between base and panel backgrounds. Selected state uses #282828.
  • Agent list: Quick-switch between agents. Active agent gets the pink dot and "default" label. Same information as TUI's Agents section.
  • MCP section: Green dot for connected, red dot + "err" label for failed. Same status visualization as TUI, but clickable for reconnect actions.
  • Goal tracker: Spans full width below both sidebar and chat, below the sidebar/main split. Same as TUI where the goal box runs edge-to-edge regardless of left nav state.
  • Sidebar width: 260px -- wider than TUI's 28 columns because the browser has more horizontal space and mouse targets need adequate click area. Collapsible (hidden by default on screens under 768px).
